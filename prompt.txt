$region = "us-east-1"

Set-DefaultAWSRegion -Region $region

try {

    $lambda = Get-LMFunctionConfiguration `
        -FunctionName "ServerlessWebApp" `
        -ErrorAction Stop

    if ($lambda.Runtime -eq "python3.12") {

        $message = @{
            Status  = "Succeeded"
            Message = "Lambda function exists and runtime is python3.12."
        } | ConvertTo-Json
    }
    else {

        $message = @{
            Status  = "Failed"
            Message = "Runtime is not python3.12."
        } | ConvertTo-Json
    }
}
catch {

    $message = @{
        Status  = "Failed"
        Message = $_.Exception.Message
    } | ConvertTo-Json
}

Push-OutputBinding -Name Response -Value ([HttpResponseContext]@{
    StatusCode = [System.Net.HttpStatusCode]::OK
    Body       = $message

try {

    $logGroupName = "/aws/lambda/ServerlessWebApp"

    # Ensure log group exists
    $logGroup = Get-CWLLogGroup -LogGroupNamePrefix $logGroupName

    if (-not $logGroup) {
        throw "CloudWatch log group does not exist."
    }

    # Get latest log stream
    $streams = Get-CWLLogStream -LogGroupName $logGroupName

    if (-not $streams) {
        throw "No log streams found. S3 trigger not fired yet."
    }

    $latestStream = $streams | Sort-Object LastEventTimestamp -Descending | Select-Object -First 1

    if (-not $latestStream) {
        throw "No recent log stream found."
    }

    # Get log events
    $events = Get-CWLLogEvent `
        -LogGroupName $logGroupName `
        -LogStreamName $latestStream.LogStreamName

    $logText = ($events.Events | ForEach-Object { $_.Message }) -join " "

    # Validate trigger activity (S3 upload event)
    if ($logText -match "s3" -or $logText -match "ObjectCreated" -or $logText -match "PUT") {

        $message = @{
            Status  = "Succeeded"
            Message = "S3 upload successfully logged in CloudWatch."
        } | ConvertTo-Json -Compress
    }
    else {

        $message = @{
            Status  = "Failed"
            Message = "CloudWatch logs exist but no S3 event detected."
        } | ConvertTo-Json -Compress
    }
}
catch {

    $message = @{
        Status  = "Failed"
        Message = $_.Exception.Message
    } | ConvertTo-Json -Compress
}

# **Scenario 1: Reviewing the BOOKIT Target Architecture and Service Selection**

## **Module 01 : Cloud-native architecture (Azure and AWS Architect)**


Nedbank's branch-appointment booking service, `BOOKIT`, is a small customer-facing app being
handed to a junior architect for a fundamentals review. Below is the target architecture diagram
description and the service selection table the design team produced when it was first built.

**Target architecture, described:**

```
Customer browser/app
   -> Azure Front Door (public entry, TLS termination, WAF)
   -> Azure App Service (Standard tier, 2 instances, autoscale 2-4 on CPU)
   -> Azure SQL Database (General Purpose, single instance, no read replica)
   -> Azure Blob Storage (booking confirmation PDFs, Hot tier)
```

**Service selection table, with the stated requirement and the service chosen:**

| Requirement | Service selected | Notes on record |
|---|---|---|
| Public entry point with basic web protection | Azure Front Door with WAF policy | Chosen over a plain Application Gateway for its WAF |
| Application hosting, no server management | Azure App Service | PaaS, avoids OS patching for a 2-person team |
| Transactional booking data | Azure SQL Database | Relational, ACID needed for appointment slots |
| Confirmation document storage | Azure Blob Storage, Hot tier | Documents are read frequently in the first 30 days |

**Availability requirement on record:** BOOKIT must remain available if a single App Service
instance fails, but a full regional outage is accepted as out of scope for this release.

**Reference notes** - background you may need. These are not clues specific to this incident.

- **Autoscale** adds or removes application instances based on a metric like CPU, within a configured minimum and maximum. Running at the minimum of 2 instances already protects against a single instance failing.
- **Hot tier** blob storage costs more per gigabyte than Cool or Archive tiers but has no retrieval fee and the lowest access latency, which suits data read often and soon.
